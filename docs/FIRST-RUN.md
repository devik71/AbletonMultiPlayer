# Перший прогін на двох машинах

Покроковий сценарій для пари Windows-машин, що грають **через інтернет** по
Tailscale. `p1` — той, у кого крутиться relay (він же гравець), `p2` — другий
гравець. Установка як така описана в [README](../README.md); тут — саме порядок
дій для спільної сесії й перелік того, що треба перевірити.

Токен на першому прогоні **не беремо**: менше рухомих частин. Додати його —
одна змінна оточення, див. README.

> **Не запускай daemon через Планувальник завдань або WMI.** Вікно daemon — це
> пульт керування (`who`, `follow`, `undo`, `pull`), і до відчепленого процесу
> ти не достукаєшся. Плюс саме в цьому вікні видно лог, який знадобиться, якщо
> щось піде не так.

## Перед стартом

На обох машинах: Windows, **Node 18+** (`node -v`), **Ableton Live 11/12**.

## p1 — relay і гравець

### 1. Впустити партнера в мережу

Обидва ставлять Tailscale і роблять `tailscale up` — кожен **своїм** акаунтом.
Далі в admin console: **Machines** → машина з relay → `⋯` → **Share…** →
надіслати запрошення партнеру. Він приймає, лишаючись у власному tailnet;
спільний акаунт не потрібен.

Своя адреса:

```powershell
tailscale ip -4          # 100.x.y.z — саме її отримає партнер
```

### 2. Фаєрвол — один раз, від адміністратора

```powershell
New-NetFirewallRule -DisplayName "AbletonMP relay" -Direction Inbound -LocalPort 19870 -Protocol TCP -Action Allow
```

Дозволу «приватні мережі» з першого запуску Node може не вистачити: адаптер
Tailscale класифікується окремо.

### 3. Код і Remote Script

```powershell
cd <тека-репозиторію>
git pull
cd relay;     npm install
cd ..\daemon; npm install
cd ..\remote-script
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Далі **повністю закрити й відкрити Live**, потім
`Preferences → Link/Tempo/MIDI → Control Surface → AbletonMP`.

### 4. Проєкт

Створити **чернетку** — пару MIDI-треків, один-два девайси, кілька сцен — і
зберегти. Потім надіслати партнеру **всю теку проєкту** разом із `.als`.

Це не формальність: uuid об'єктів лежать усередині файлу, тож зібраний наново
сет із такою самою структурою не підійде.

### 5. Вікно 1 — relay

```powershell
cd <тека-репозиторію>\relay
npm start
```

Очікується: `relay слухає ws://0.0.0.0:19870 (proto 1)`.

### 6. Вікно 2 — daemon

```powershell
cd <тека-репозиторію>\daemon
node index.js --author p1 --session jam --relay ws://127.0.0.1:19870
```

Свій relay — завжди через `127.0.0.1`: це прибирає будь-які питання з іменами
й резолвом.

## p2 — другий гравець

### 1. Мережа

Прийняти запрошення Tailscale своїм акаунтом і перевірити, що машина з relay
видна:

```powershell
tailscale status         # у списку має бути машина p1 з адресою 100.x.y.z
```

### 2. Код і Remote Script

```powershell
git clone -b agent/relay-hardening https://github.com/devik71/AbletonMultiPlayer.git
cd AbletonMultiPlayer\daemon
npm install
cd ..\remote-script
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Повний рестарт Live → `Preferences → Link/Tempo/MIDI → Control Surface → AbletonMP`.

### 3. Проєкт

Розпакувати теку від p1 і відкрити **той самий** `.als`.

### 4. Daemon

```powershell
cd AbletonMultiPlayer\daemon
node index.js --author p2 --session jam --relay ws://<адреса-p1>:19870
```

Адреса — та сама `100.x.y.z` з `tailscale ip -4` у p1, або MagicDNS-ім'я виду
`misha.tailXXXX.ts.net`. **`.local`-імена не використовувати**: Node їх не
резолвить і падає з `getaddrinfo ENOTFOUND`.

## Перевірка, що ланцюг зібрався

У кожному вікні daemon має бути:

```
bridge підключився: Live 12.3.x, script 0.19.0-dev
relay: head=..., у сесії p1, p2
```

Далі відкрити `http://<адреса-p1>:19870/health` — там мають бути обидва гравці,
їхні IP і версії Live та скрипта.

## Сценарій прогону

Порядок від «має працювати точно» до «вперше виконується в живому Live».

**1. База.** Фейдер у p1 → їде в p2, і навпаки. Далі темп, запуск кліпа,
перейменування треку, зміна кольору.

**2. Ноти.** Намалювати кілька нот у Session-кліпі → мають з'явитись у партнера.

**3. Локи.** Поки один крутить фейдер, у другого в лозі daemon:
`редагують: p1 — <трек>`.

**4. Присутність.** Поклацати по треках → у партнера `дивляться: p1: <трек> / <сцена>`.
Це перший код, що читає `song.view` у справжньому Live.

**5. Follow.** У p2: `follow p1`, далі p1 клацає — вид p2 має їхати за ним.
Три захисти перевіряються окремо:

- p2 клацає сам → follow має замовкнути на 5 секунд;
- p2 озброює трек і запускає транспорт → `follow призупинено: трек озброєний`,
  вид не смикається (це захист від мовчазного перенаправлення MIDI);
- p1 робить `follow p2`, поки p2 слідує за ним → відмова
  `p2 уже слідує за тобою`.

**6. Undo.** p1 змінює фейдер двічі, p2 виконує `undo p1` → значення
повертається **на машині p1**, у журналі додається рядок.

**7. Знімки.** В обох `state`, порівняти digest. Потім у p2: `pull p1` і
подивитись на список «Бракує ось чого».

**8. Семпли.** Покласти невеликий `.wav` у `Samples` теки проєкту → має доїхати
байт у байт. Файли більші за ~12 МБ поки не пробувати: відома межа з буфером
relay (див. «Межі» в README).

## Що зібрати, якщо не працює

Найцінніше — **лог bridge з обох машин**: `%APPDATA%\AbletonMP\bridge.log`.
Рядки `EXC in` — це виняток усередині процесу Live, і саме вони найважливіші.
Плюс вивід обох вікон daemon і вікна relay.

### Типові симптоми

| Що видно | Причина |
|---|---|
| `getaddrinfo ENOTFOUND ...local` | `.local`-ім'я не резолвиться; узяти `100.x.y.z` з `tailscale ip -4` |
| нескінченні `підключаюсь до …` | relay недоступний; це штатний реконект із паузою до 10 с, а не зависання |
| `script 0.18.0` у лозі | Live тримає стару копію скрипта в `sys.modules` — потрібен **повний** вихід із застосунку, перезавантаження сету не досить |
| `версії скрипта різні` | на машинах різні версії коду; оновити обидві й перезапустити Live |
| `relay error [bad_token]` | токен є лише в одного боку: він має бути або в обох, або в жодного |
| `/health` віддає `401` | relay під токеном; `http://host:19870/health?token=...` |
| вікно daemon повертається після закриття | процес підіймає Планувальник завдань або WMI; знайти й вимкнути (README, «Зупинка») |
| подія не застосувалась, у лозі bridge warning про uuid | сети розійшлись структурно; `pull <author>` і подивитись на список прогалин |

## Зупинка

`Ctrl+C` у кожному вікні — спершу daemon, потім relay. Порядок не критичний:
журнал на диску консистентний після кожної події. Remote Script зупиняється
разом із Live або через `Control Surface → None`.
