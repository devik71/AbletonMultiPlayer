title: "Обхід меж LOM: три канали, і жоден не кодується до проби"

Дії поза LOM (автоматизація, групування треків, take lanes, стан VST, Freeze) закриваються трьома механізмами, описаними у vision.md: XML merge через .als (§7), UI Automation Layer через AX (§12), запис автоматизації відтворенням (§11, проба 4). Кодування жодного не починається, доки не завершена його проба: buildable на нашому форматі .als, збереження abletonmp_id при копії треку, наявність AX-дерева в Live.

Виміряно по коду, не на живому Live: після XML merge трек приносить свій uuid на собі (set_data/abletonmp_id), а кліпи, ланцюги й Arrangement -- ні: вони живуть мапою abletonmp_registry на Song, яка лишається у файлі партнера. І саме File > Revert робить стикування можливим -- _restore_registry поважає збережений id, а живий шлях _diff_tracks -> _persist_registry перезаписує успадкований id власним (навмисно, так ловиться Ctrl+D).

**Чому:** Кожен із трьох механізмів тримається на емпіричному припущенні, яке ще не перевірене. Написаний навколо мертвого припущення код -- чистий збиток, а половинчаста ідентичність після merge -- саме та деталь, яку легко не помітити й отримати трек без кліпів.
