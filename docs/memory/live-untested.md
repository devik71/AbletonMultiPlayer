tools/pair-live.mjs перевіряє автоматично двадцять речей в обидва боки (темп, гучність, назви, присутність, локи, undo, кліп із нотами, треки, сцени, локатори, темп сцени, мікшер ланцюга в раку, стан девайса повз параметри, маркери семплу, стоп-кнопка слота, кліп у лінійці, audio-семпл у слот, warp-маркери, знімки, diff). Окремо перевірено вручну: семпли байт у байт через межу файлових систем, apply_gap, Ableton Link, семпл на пад Drum Rack Windows -> macOS. НЕ ПЕРЕВІРЕНО НА ЖИВІЙ ПАРІ: групування треків (LOM не вміє створювати групи), запис кліпа під час гри (потрібні руки й реальний вхід), перетягування девайса з браузера мишею. ОКРЕМО -- ВИПРАВЛЕННЯ, ЩО ЧЕКАЮТЬ ЖИВОГО ПІДТВЕРДЖЕННЯ (коміти af99490 і 7d8134c, обидва після зупинки Live): переміщення кліпа має давати ClipDelete разом із ClipCreate; параметри всередині раків мають доїжджати, якщо кити в обох однакові. У другому є непідтверджене припущення: реєстр зіставляє проксі Live через ==, а ланцюги тепер беруться через pad.chains замість device.chains -- якщо припущення хибне, девайси всередині падів стануть недосяжні, тобто вийде гірше за баг. Перевірити першою ж командою після старту.

**Чому:** Лишились рівно ті три, які автоматизувати нічим або які впираються в межу LOM. А два свіжі виправлення прогнані лише npm test -- на живому Live жодне з них ще не бачили, і одне з них має ризик регресії, гіршої за сам баг.
