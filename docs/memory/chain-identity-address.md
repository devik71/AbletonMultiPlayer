title: Ланцюг раку адресується нотою пада, а не позицією
scope: all
status: current
updated: 2026-08-30
---

Локатор ланцюга, з якого рахується його uuid, більше не містить ні позиції серед заповнених ланцюгів, ні назви. Для падів Drum Rack адреса -- нота (drum_pads[i].note); для звичайних раків лишились idx+name. Порядок кандидатів на uuid теж змінено: канонічний запис партнера, далі ДЕТЕРМІНОВАНИЙ хеш від локатора, і лише потім збережений у .als id. Раніше збережений id стояв вище за хеш.

**Чому:** Хеш від локатора -- єдине, що здатне звести ланцюг, якого партнер ніколи не бачив: обидві машини рахують його однаково. Локально намінтований id не може звести нічого за визначенням, а стояв вище -- і машини трималися кожна за своє. На живій парі 29 серпня це давало 53 'device at chain path is absent' за прогін: параметри всередині раків не їхали взагалі. Виміряно окремо, що персистенція НЕ винна -- обидва збережені в .als id точно дорівнювали хешу; винен був порядок і те, що локатор рахувався з вмісту. Межа лишається: якщо раки в партнерів різні, жодна адресація не допоможе -- мапити нема на що.
