# AbletonMP probe — розширення для Extensions SDK

> **Статус: заморожено, у живому Live не запускалось жодного разу.**
>
> Extensions потребують Live 12 **Suite** 12.4.5+. На акаунті розробника
> Live Standard, тож перевірити probe немає на чому: вкладки «Extensions»
> у налаштуваннях бети немає, Extension Host не стартує. Код написаний,
> типізується (`tsc --noEmit` чистий) і збирається — але всі чотири питання
> нижче лишаються **без відповідей**. Не посилайтесь на нього як на робочий шар.
>
> Щоб розморозити: ліцензія Suite → бета 12.4.5+ з Centercode → тарболи SDK
> у `vendor/` → `npm start`.

Це **не** шар синхронізації. Це чотири питання до живого Live, на які не
відповідають ні документація, ні емулятор. Поки на них немає відповідей,
будувати поверх Extensions SDK нічого не варто.

| # | Питання | Як перевіряється |
|---|---|---|
| 1 | Чи Extension Host справді довгоживучий і чи тримає відкритий WebSocket | `alive` кожні 30 с у `probe-server`; лишити на годину і подивитись, чи не обірветься |
| 2 | Чи вантажиться модалка з `http://localhost` на Windows (WebView2) | пункт контекстного меню; сторінка друкує власний `origin` і результат `fetch` до демона |
| 3 | Чи працює `insertDevice` і що саме він приймає як `deviceName` | команда `insert` у `probe-server` |
| 4 | Чи витримує звірка «індекс + назва» те, що handle'и не переживають переміщення | `resolveTrack` падає при розбіжності — переставте треки і повторіть |

## Передумови

- **Live 12 Suite Beta 12.4.5+** — Extensions немає ні в стабільному Live, ні в
  Standard/Intro/Lite.
- **Node 24.16+** (SDK вимагає; менша версія дає лише `EBADENGINE` warning,
  бо сам хост несе власний `node.exe`).
- **SDK zip із бета-кабінету Centercode.** У репозиторії його немає і не буде:
  ліцензія Ableton забороняє поширювати SDK поза власним застосунком.
  Розпакуйте zip і покладіть два тарболи в `vendor/`:
  ```
  vendor/ableton-extensions-sdk-1.0.0-beta.1.tgz
  vendor/ableton-extensions-cli-1.0.0-beta.1.tgz
  ```
- **`.env`** із шляхом до хоста (теж не в репозиторії):
  ```
  EXTENSION_HOST_PATH=C:\ProgramData\Ableton\Live 12 Beta\Program\ExtensionHost\ExtensionHostNodeModule.node
  ```

## Запуск

1. У Live: **Settings → Extensions → Developer Mode**. Без цього Live тримає
   хост сам і `npm start` до нього не достукається.
2. Термінал 1 — фейковий демон:
   ```
   npm run probe-server
   ```
3. Термінал 2 — розширення:
   ```
   npm install
   npm start
   ```
4. У Live клацнути правою на треку → **AbletonMP: probe…**

У першому терміналі працюють команди:

```
snapshot                        назви треків і девайсів
insert 0 Bass Reverb            вставити стоковий девайс зі звіркою назви треку
quit
```

## Що це навмисно не робить

Не чіпає демона, релей і Remote Script. Не пише в журнал. Не має ідентичності
через uuid — `set_data` розширенню недоступний, тож трек адресується парою
«індекс + назва», і при розбіжності операція падає, а не застосовується
навмання. Справжня інтеграція мусить брати uuid від демона; probe свідомо
показує, наскільки крихка адресація без нього.
