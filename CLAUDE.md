# Робота над цим проєктом

## Спершу прочитай пам'ять

```
node tools/memory.mjs list      # що відомо
node tools/memory.mjs verify    # чи це досі правда
```

[`docs/memory/`](docs/memory/INDEX.md) тримає те, що інакше губиться при
переїзді між машинами: чинна гілка, стан живих перевірок, ухвалені рішення,
особливості оточення. `verify` не вірить записам на слово — він виконує їхні
команди перевірки й показує розбіжність.

**Перед тим як спиратись на факт із пам'яті — запусти `verify`.** Запис без
`verify` і старший за 30 днів `check` позначає окремо.

## Куди що писати

| Що саме | Куди |
|---|---|
| Виміряна поведінка Live (що LOM уміє, як поводиться, де межа) | [`docs/COVERAGE.md`](docs/COVERAGE.md), [`docs/PROTOCOL.md`](docs/PROTOCOL.md) |
| Рішення, стан робіт, оточення, чинна гілка | `docs/memory/` через `tools/memory.mjs` |
| Візія, інваріанти, роадмапа | [`vision.md`](vision.md) |

Межа проста: у `COVERAGE.md` і `PROTOCOL.md` — **що робить Live**; у пам'яті —
**що робимо ми і в якому стані це зараз**. Дублювати не треба, у пам'яті досить
посилання.

Нові знання додаються так:

```
node tools/memory.mjs add <id> --type state|decision|env|reference \
    --title "..." --body "..." --why "..." [--verify "команда" --expect "текст"]
node tools/memory.mjs supersede <старий-id> --by <новий-id> --reason "..."
```

`add` із наявним id **оновлює** запис, а не плодить другу правду. Застаріле не
видаляється, а скасовується через `supersede` — видно, що змінилось і чому.

## Живі перевірки

Live виконує **копію** скрипта в User Library, а не файли репозиторію. Після
кожної правки:

```
node tools/check-install.mjs --install   # і перезапустити Live
```

Без цього живий прогін перевіряє старий код і не підтверджує нічого. Так уже
було: десять днів на копії від 14 серпня.

Перевіряти LOM наживо можна через локальний HTTP-API моста:

```
POST http://127.0.0.1:19847/api/exec   заголовок X-AbletonMP-Token
{"actions":[{"op":"lom_call","path":["tracks",0],"method":"insert_device","args":[]}]}
```

Виклик без аргументів віддає C++ підпис у тексті помилки — це найшвидший
спосіб дізнатись, що метод справді існує і що він приймає. Токен лежить у
`~/.abletonmp/chat_token`.

## Правило про довідник LOM

[`.claude/skills/ableton-lom`](.claude/skills/ableton-lom/LOCAL-NOTES.md) —
карта, а не ґрунт. Мовчанка довідника не означає «такого немає» (`set_data`
там немає, а вся наша ідентичність на ньому), і він помиляється
(`insert_device` заявлений як `None`, насправді повертає створений девайс).
Перед тим як спертись на факт — перевір його на живому Live.

## Тон коду й документації

Українською. Коментар пояснює **чому**, а не переказує код. Межі й компроміси
називаються вголос: «краще дірка, яку закриє знімок, ніж мовчки покладений не
той девайс». Не писати, що щось працює, поки воно не працювало в живому Live.
